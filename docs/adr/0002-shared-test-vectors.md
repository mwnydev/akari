# 0002 费用与分期解锁的共享测试向量

- 状态：已采纳
- 日期：2026-10-19

## 背景

手续费、gas 费、争议费和分期解锁要在 Solidity、Rust、TypeScript 三处计算（计划第 14 节）。三边稍有不一致就会出现「界面显示的金额与链上实际扣的不同」。

## 决定

- `test-vectors/fees.json` 是这些规则的唯一定义：`rules` 字段用文字写清公式，`fees` 与 `streams` 是带期望值的用例。
- 金额一律用最小单位（USDT 6 位）的十进制字符串，避免 JSON 数字精度问题。
- 三边的测试都直接读取这个文件逐条断言：`contracts/test/FeeMath.t.sol`、`backend/crates/core`、`frontend/packages/fees`。
- 关键约定：
  - 「各半」时买家承担 `floor(total / 2)`，卖家承担余数（多出的 1 个最小单位归卖家）；手续费和基础固定 gas 费都按这个规则拆。
  - 免费活动期间按活动费率计算，最低手续费失效。
  - 争议费以订单实际手续费为基数；手续费为 0 时以最低手续费为基数。
  - 分期可解锁净本金扣除卖家承担的手续费与基础 gas 费；已解锁按整数周期向下取整，最后一期拿到余数。
- 修改规则 = 改这个文件 + 三边实现，在同一个 PR 内完成。

## 后果

任何一边的实现漂移都会在 CI 中失败。新增规则（如保证金违约赔付比例）同样先加向量再写代码。
