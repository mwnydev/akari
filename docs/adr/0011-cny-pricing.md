# 0011 人民币计价：卖家自选币种与自定汇率，不接外部汇率源

- 状态：已采纳（站长决定，2026-10-19；取代同日的「论坛统一 USD→CNY 汇率」草案）
- 日期：2026-10-19

## 背景

用户习惯按人民币思考价格，但担保资金在链上只能是 USDT。曾考虑由论坛接入实时汇率源统一换算，但那会引入外部依赖，还给了平台改动换算结果的空间（汇率源出错或签名私钥被盗时可以压低卖家所得）。

## 决定

1. **不接任何外部汇率源。** 换算一律使用卖家自己设定并签名的固定汇率。
2. **拍卖**：
   - 卖家挂拍时选择币种：USDT 或人民币。起拍价、加价幅度、保留价、出价都用该币种。
   - 选 USDT：与原计划相同。
   - 选人民币：卖家同时设定固定汇率（每 1 USDT 合多少元，精确到 0.0001），与拍卖条件一起写进 EIP-712 拍卖授权、用 Face ID 签名。出价页提示「按卖家设定汇率 R，折合 X USDT」。
   - 成交：平台成交证明只带成交价（拍卖币种）；`createFromAuction` 用卖家签名的汇率在链上换算为 USDT（向上取整到最小单位），并检查成交价 ≥ 卖家签名的保留价。平台无法改动汇率或保留价，私钥被盗也一样。
   - 付款页同时显示人民币成交价、卖家汇率、应付 USDT。
3. **普通交易帖与担保报价**：以 USDT 标价，链上付款金额与标价一致。卖家可选填一个参考汇率，页面据此显示人民币参考价；不填只显示 USDT。参考价只是参考，买卖双方可在私信里自行商量，报价卡片以卖家签名的 USDT 金额为准。
4. **合约改动**（第 12 周冻结前完成）：拍卖授权新增 `currency`（USDT / CNY）与 `cnyPerUsdt`（4 位小数定点数，仅 CNY 时非零，合约写死合理范围以防填错）；`createFromAuction` 按上述规则换算与校验。

## 后果

- 没有汇率服务这个外部依赖，也没有平台操纵换算的风险。
- 卖家汇率可能与市场价不同；这是卖家自己的定价，买家出价前就能看到折合的 USDT，结算时不会因汇率变动产生纠纷。
- 以人民币计价交易加密货币在中国大陆有更高的监管风险；计划第 1 节「法律合规暂不处理」，此处记录以备后续评估。
