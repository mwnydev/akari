# 0013 管理角色简化：站长、管理员、版主；只有涉及钱才要 Passkey

- 状态：已采纳（站长决定，2026-10-19；取代同日多版草案，并修订 plan 第 7、9 节）
- 日期：2026-10-19

## 背景

计划原设五种管理角色（站长、超级管理员、管理员、版主、仲裁员），管理人员一律 Passkey 登录、后台操作。对刚起步的小论坛来说人手不够，日常管理也太麻烦。计划第 1 节原则 3：「门槛只放在动钱和改权限这两类操作上」。

## 决定

1. **只保留三个角色**：
   - **站长**：合并原「站长」与「超级管理员」。拥有全部管理权限，进后台（`administrator.akari.cc`）管理金库与运营钱包记账、薪资、任免管理员与版主、站点与链下参数、财务报表；大额双人裁决意见不一致时终裁；无法裁决时转公开投票。
   - **管理员**：在论坛里管理用户、板块、内容、举报、禁言与封禁（含永久封号、IP / 设备封禁），并**负责仲裁**（论坛内专用的仲裁页面）。不进后台。
   - **版主**：只管自己负责的板块：置顶、精华、锁帖、隐藏、移动、删帖（软删除）、禁言（≤ 7 天）、禁拍（≤ 30 天）。不进后台。
2. **不设单独的仲裁员职位**：仲裁是管理员与站长的权限。案件在他们之间随机分配；与当事人有关联或 90 天内有交易的自动回避；≥ 200 USDT 两人独立裁决，不一致由站长终裁；申诉由未参与的另一人复核；计酬只按工作量与按时率，绝不与裁决方向挂钩（plan 第 7 节其余规则不变）。
3. **不设「管理模式」**：管理员、版主用邮箱验证码登录，登录后就是普通用户界面加上其角色的管理功能，不需要 Passkey。
4. **只有涉及钱才要 Passkey**：
   - 站长登录后台：后台 Passkey（RP ID `administrator.akari.cc`；闲置 2 小时、最长 12 小时；敏感操作 5 分钟内再验证）；
   - 管理员 / 站长在论坛**提交裁决**时：论坛 Passkey 确认（RP ID `akari.cc`，只用于签署裁决），因为裁决决定托管资金的分配。
5. **仲裁 Safe**：3 人中 2 人签名，签名人为 2 名管理员 + 站长（三人必须是不同的人，签名设备分处保管）。
   - 平时：两名管理员审案、意见一致，由他们俩签名执行，站长不参与；
   - 两人意见不一致：站长终裁，与赞同终裁意见的管理员一起签名执行；
   - 小额争议（< 200 USDT）由一名管理员审，与另一名管理员或站长一起签名执行；
   - 不设 2 人都必签的 Safe：任一管理员离职、丢失签名设备或拒签时，所有争议都会卡到 30 天超时兜底；站长作为第三签名人同时承担终裁与顶替；
   - 补偿「审案人即签名人」的保护：裁决公示后先经 72 小时申诉期，无人申诉才进入 Safe 执行（有申诉则等复核结果）；每份裁决连同理由和证据链接自动推送站长，站长可在执行前叫停；
   - Safe 仍只能执行已公示的裁决，`resolve` 只能把钱分给买卖双方。
6. **兜底措施**（管理账号只靠邮箱保护，不增加日常操作）：
   - 管理人员新设备登录：除本人邮件外，实时推送管理员 Telegram 群；
   - 管理操作限速；短时间内删帖 / 封号等超过阈值即推送管理员群，并暂停该账号的管理权限，待站长确认后恢复（阈值站长在后台调）；
   - 所有管理操作可撤销、写只增审计日志；站长可一键撤销某账号在某时间段内的全部管理操作；
   - 上线前提醒管理人员给邮箱开启双重验证。

## 后果

- 原计划「站长和超级管理员必须是两个不同账号」「超级管理员负责发薪且不能给自己发薪」等相互制衡取消：管钱、管人、终裁集中在站长一人。这是小论坛的合理取舍；资金仍只走 Safe 多签，任何角色都动不了合约里的用户托管资金。
- 薪资钱包改由站长控制（与金库同为站长的签名设备，但余额只放当月预算）。
- 第 3 轮的论坛侧管理接口保留，按三个角色细分权限，并补上第 6 条的兜底措施；新增论坛仲裁页面与裁决 Passkey 确认。
