# 0014 仓库可见性：上线稳定前主仓库公开，之后拆出合约与钱包公开仓库

- 状态：已采纳（站长决定，2026-10-19）
- 日期：2026-10-19

## 背景

合约必须公开（链上验证、多方 AI 审计、公开审查期与漏洞赏金，ADR 0007）。钱包前端决定用户签什么，公开源码 + 可复现构建可让任何人核对线上页面（T-02），紧急取回页在论坛关停时也能由他人自行部署。论坛、后端、后台、代付服务含防刷与运营逻辑，长期不宜公开。私有仓库的 GitHub Actions 有每月分钟数限制，开发期 CI 频繁。

## 决定

1. **上线并稳定前**：`mwnydev/akari` 保持公开（不受 Actions 分钟数限制）。
2. **公开期间的约束**：密钥从不进仓库（gitleaks 门禁）；防刷规则、风控阈值等不想公开的参数不写死在代码里，放数据库站点设置由站长在后台调。
3. **合约冻结时（第 12 周，2027-01-04）**：新建公开仓库 `akari-contracts`，只放冻结版本（不带开发历史）、共享测试向量、审计报告、部署地址、漏洞赏金说明。
4. **上线前（约第 20 周）**：新建公开仓库 `akari-wallet`（钱包前端及其依赖的公共包），由 CI 从主仓库自动同步，每次发布附构建哈希；同步流程上线前演练。
5. **上线稳定后**：`mwnydev/akari` 改为私有，开发仍只在主仓库进行。

## 后果

- 上线前论坛源码公开，安全不能依赖代码保密（本来也不应依赖）。
- 公开仓库是单向同步的产物，不接受在公开仓库直接改代码；外部反馈经 issue / 赏金渠道回到主仓库。
